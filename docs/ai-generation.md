# AI 创作：页面、站点、组件与恢复设计

## 开始使用

1. 点击右下角「AI 创作」气泡，在聊天窗口右上角打开「AI 模型配置」。
2. 选择 OpenAI Responses 或 Anthropic Messages，填写 API 基础地址与自己的密钥；默认地址已经填好，兼容服务可替换地址。
3. 点击「读取模型列表」选择模型，或直接填写模型 ID。思考强度留空沿用模型默认值；旧版 Anthropic 模型可按需选择手动思考预算。
4. 保存配置，在聊天顶部选择 **生成页面**、**创建整站** 或 **创建组件**。页面模式可选择当前页面、此前保存的 AI 页面或账号的云端页面；组件模式使用独立草稿，不替换当前页面。「＋」新建当前模式的草稿。
5. 发送需求后会连续生成整个任务；未完成的回复自动续写，无需逐组件点击。需求缺少会明显影响结果的选择（视觉风格、目标屏幕与画布尺寸、主要区块）时，AI 会先提问并给出选项：点选后「确认并继续」，或「按推荐生成」，也可以在输入框补充文字一起发送。聊天显示连接阶段、思考内容的滚动预览、当前步骤、轮次、修改次数和耗时。生成中工作台暂时锁定，点击「暂停」即可接手编辑；手动暂停后点击「继续生成」从当前画布续写。刷新后检查点与页面不同时，先选择恢复检查点或使用当前画布。
6. 组件模式的结果可直接预览、编辑代码、添加到页面或上传云端。聊天底部的垃圾桶可移除 AI 对话记录，释放记录名额；这不会删除当前画布、组件库副本或云端页面。

## AI 整站创作

从“从任务或模板开始…”选择 **用 AI 创建完整站点**，或在 AI 面板选择 **创建整站**。整站模式复用同一套模型配置，但有独立的站点会话与检查点，不替换现有单页或组件对话。

1. 描述站点目标，点击 **规划站点**。规划阶段只读取页面 ID、名称、路径、类型、SEO 设置、布局和组件数量，不修改画布。也可以点击 **解释当前结构**，无需发起模型请求即可查看页面、路由、共享布局和缺失链接。
2. 核对计划中的页面、路径、共享布局和删除范围。只有点击 **确认计划，生成整站** 后才开始生成。已有页面保留稳定 ID；计划外页面和布局不能由模型直接修改，首页不能由 AI 删除。
3. 生成阶段使用当前计划与站点草稿，逐条返回完整页面或共享区域，并通过 `validatePage`、站点引用、路径和大小校验。每个完成项先写入浏览器检查点，当前画布不变；全部必需页面和布局完成后才一次应用，形成 **一个编辑器撤销步骤**。
4. 网络中断或手动暂停会保留最后检查点。重新打开后可继续当前计划，不自动消耗额度；整站任务不会在后台自动续写或发布。若计划后站点已被其他操作修改，最终提交会拒绝覆盖，保留草稿供恢复或重新规划。单页与整站 AI 任务不能同时修改同一作品。
5. 完成后可在“页面”面板继续手动编辑，或恢复生成前版本。游客草稿照常自动保存；已有云端站点只标记 **待保存**，需要用户显式保存或发布。AI 不自行创建云端记录、更新分享快照或执行外部写入。

整站 AI 返回的完整页面会在严格校验前归一化画布高度：普通页面和侧栏为 **320–6000 px**，页头和页脚为 **320–1000 px**。低于最小值、缺失高度或数字字符串会转换为有效值，但不会压缩已有组件及底部留白所需的空间；内容超过可用高度时会暂停并提示减少布局内容或拆分页面，不会静默裁切。页面与共享布局合并后的高度仍不能超过 **6000 px**。此修正只用于整站 AI 输出，不放宽手动导入或既有保存校验。

整站协议在 `src/lib/ai/site-ai.ts`：`sitePlan` 描述确认范围与可选公开数据源，`sitePage` 提供完整页面，`siteLayout` 提供共享页头、页脚或侧栏，`dataSource` 提供内容集合、公开静态数据或浏览器直接读取的 GET 配置。它们与单页逐组件操作分开处理；`done` 仍需供应商正常完成响应，不能掩盖无效记录。计划、生成前快照、当前草稿、任务与消息保存在当前浏览器的 `animate-studio:ai-site:v1:<账号或游客>:<站点 ID>`，不上传云端；模型密钥只用于请求配置，不进入这些检查点。刷新时未完成的 generating 状态按暂停处理。

计划中的页面可携带 SEO 标题、描述、分享图和收录设置，使用与手动编辑相同的校验；未列入修改范围的既有 SEO 会保留。AI 不会因此更新公开 HTML、提交搜索引擎或承诺实际排名，动态详情和 404 不进入静态站点地图。公开元信息仍需用户通过发布中心更新。

## AI 与站点媒体

图片、Logo 和 SEO 分享图可复用当前站点已有的 `asset:<id>` 引用。模型上下文只包含这些引用，不包含图片二进制、对象存储键或账号信息。未知素材引用会在单页和整站操作的应用边界被拒绝，模型不能通过虚构 UUID 假装已经上传文件。

上传、选择、移除和迁移失败重试由用户在媒体库中完成。AI 不操作 IndexedDB、私有文件存储或 R2，也不会自动发布、恢复公开版本或修改素材所有权。公开图片只能来自当前已发布快照，移除当前引用后不会继续通过该分享地址暴露；历史回滚需要时再恢复访问。

## AI 后台与数据任务

整站计划可以声明静态 JSON、公开 REST GET 或嵌入站点的 **内容集合**，同时生成后台页面、共享侧栏、动态列表和详情。集合使用 `fields` 声明文本、多行文本、数字、布尔、链接和图片字段，`records` 保存明确标记的示例内容；列表使用 `mode:"collection"`，详情使用 `mode:"single"`，通过 `detailField` 与 `detailParameter` 匹配动态路由，找不到记录时明确报错，不会回退第一条。

计划确认后，`dataSource` 操作只把配置写入草稿，不测试接口、不发起网络请求，也不执行表单写入或发布。公开读取仍需用户在“数据与脚本 → 数据源”中实际测试连接。集合随站点保存、发布、回滚和导出，不是独立远程 CMS 或公共写库；AI 不能声称示例内容来自真实业务数据库。

AI 不能创建认证请求头、代理传输、凭据引用或 POST/PUT/PATCH/DELETE 数据源。表单可以保留空提交目标，或引用用户已有的写入配置；关联凭据、测试真实接口、实际提交和发布始终由用户在界面中完成。结构解释会区分内容集合、静态数据和公开接口，不声称示例配置已经连接到真实服务。

发送给模型的站点上下文会移除已有数据源的凭据引用、请求头、查询参数、请求体、静态内容、集合记录正文以及 URL 中的查询部分；只保留集合结构、详情匹配和分页等必要配置，不会修改实际数据源。集合图片与页面图片遵守同一素材白名单，AI 不能通过集合记录绕过限制伪造上传。`tests/collection-ai.test.mjs` 使用确定性模拟输出验证这些边界，不代替真实模型质量验收。

`tests/ai-data.test.mjs` 使用确定性模拟输出验证这些边界和原子提交，不代替真实模型验收。

## AI 看板与图表

整站任务可以把已确认的静态或公开 REST 集合绑定到 **数据图表**，生成趋势、比较和构成看板。AI 使用与手动编辑相同的 `chartType`、`categoryField` 和 `dataColumns` 聚合配置；折线/面积用于趋势，柱/条形用于比较，饼/环用于非负构成。类型切换不清空映射，筛选变量必须是同页已定义的文本变量。

AI 需要说明静态全量或 REST 当前页的统计范围，不能把当前页聚合冒充全量结果，也不能虚构已连接的接口。单页任务不能创建站点数据源，因此只能使用明确标记的图表示例，或引导用户在数据源面板中继续连接；不会绕过站点数据源权限。图表点选筛选、SVG/PNG 下载、数据表和放大视图都复用真实渲染器，不是额外生成的静态图片。

看板生成继续遵守计划确认、平台校验、独立检查点、最终修订检查和原子提交。`tests/ai-data.test.mjs` 覆盖确定性的图表示例、共享数据源和映射保留；真实模型生成质量未在本轮调用验证。手动配置步骤见 [数据图表与看板](user-guide.zh-CN.md#数据图表与看板)。

## 用户流程与数据边界

右下角悬浮气泡展开 AI 聊天窗口。用户选择当前页面、浏览器中保存的 AI 页面或自己的云端页面，也可以创建空白页面；输入需求后，模型逐组件更新画布。模型配置只在界面编辑并保存在当前浏览器，包含供应商、基础地址、密钥、模型、思考设置及输出上限。请求由浏览器直接发往用户配置的服务，不经过本应用服务器，不读取服务端环境变量。配置不进入页面 JSON、分享快照、导出文件或聊天上下文。

模型会读取目标页面或组件草稿中嵌入的自定义组件源码，以继续修改和纠错；整个组件库只提供名称、说明、实例字段和默认尺寸等摘要，账号组件在打开助手后按需读取列表。引用组件时，应用读取该条定义并验证账号和页面仍未改变。库中的其他组件源码不会一次性全部发送给模型。

## 创建与复用自定义组件

- 从 **组件 → 我的组件 → AI 创建组件** 进入，或在 AI 聊天中切换 **创建组件**。描述外观、可编辑字段与交互，例如“创建一个可切换月付和年付价格的卡片”。组件草稿与当前页面分开保存，生成不会替换原页面；点击 **添加到页面** 才插入实例。
- 页面模式也允许 AI 按需求开发自定义组件，并复用本机或账号组件库中的组件。生成的代码使用已有 HTML / CSS / JavaScript 组件格式，完整校验后才运行和保存。
- 新生成或修改的源码自动保存到本机“我的组件”；同一生成物重试不会重复创建或提高版本。已有源组件在其他地方被修改时会报告修订冲突，不静默覆盖。
- 登录后点击结果上的 **上传到云端**，成功后可在其他设备的账号组件库复用；继续修改结果后可 **更新云端组件**。上传失败时本机组件和 AI 检查点仍保留。上传组件不会自动发布分享链接。
- 本机与账号组件库各有独立的一级文件夹，可创建、改名、筛选和移动组件。删除文件夹只把成员移到“未分组”，不会删除源码；分组变化不提升代码版本。完整管理步骤见 [自定义组件设计器](custom-components.zh-CN.md)。

组件内部使用 `component.props`、`component.theme`、`component.onProps()`、`component.log()` 和 `component.openLink()`，不是页面脚本的 `ctx` API。自定义组件可以操作自身文档和局部状态，但不能直接读写页面变量；页面点击联动和实例字段绑定仍使用现有机制。

支持 OpenAI Responses 与 Anthropic Messages；配置窗口读取供应商的 `/models` 列表，也允许手填兼容模型名称。OpenAI 使用 `reasoning.effort`，并默认请求 `reasoning.summary: "auto"`；不支持摘要的模型或兼容接口可在配置中关闭「请求思考摘要」。Anthropic 支持默认、自适应、关闭及手动预算，并可设置 `output_config.effort`。各模型支持的值不同，思考强度和 Anthropic 思考模式未设置时不发送对应字段；不把不支持的配置自动改成其他值。Anthropic 浏览器直连使用官方 SDK 的浏览器访问请求头。自定义兼容接口必须允许浏览器 CORS；浏览器或供应商拒绝连接时明确报错，不绕过限制。

## 为什么采用 NDJSON 操作流

整页 JSON 必须等全部生成后才能解析，输出成本也随着已有组件数量增加。通用 JSON Patch 使用深层路径，容易产生数组索引偏移。这里采用按稳定组件 ID 寻址的 NDJSON：每行一个完整 JSON 对象，一个对象最多改变一个组件。无需发送工具定义中的完整组件属性 Schema，不依赖供应商私有会话 ID，两个 API 使用同一协议。

这是经校验的结构化文本协议，不宣称供应商 JSON Schema 强约束。一次失败会中止当轮请求、重新发起一轮（推理模型每轮都要重新思考，往往要几十秒），所以只对无法确定意图的错误这样处理，常见的小偏差就地修正：

- 不以 `{` 开头的行（Markdown 围栏、夹在记录间的说明句）不可能是操作，直接跳过；以 `{` 开头但不完整或非法的 JSON 仍然中止。
- 数值超出范围时夹到边界（`fontSize`、`padding`、`radius`、`duration`、`contentScale` 并取整），颜色去掉透明度（`#RRGGBBAA` → `#RRGGBB`）；由共享校验器明确定位为无效的属性（未知键、非法枚举、不安全链接等）只丢弃该属性，记录的其余部分照常提交。
- 按钮的 `background` 会铺满整个组件外框，模型几乎总是想设置按钮填充色，因此转为 `accent`（已设 `accent` 时直接丢弃）。
- 越过页边距的位置移回边距内，宽度不超过内容区；组件落在画布下方时自动加高画布（不超过 6000），`page` 操作也不会把画布缩到已有组件以下。仍放不下或水平尺寸冲突时照常报错。

属性修复依据共享校验器的字段路径，不拆开 `value/max` 等关联值逐个试验。关系错误仍交给模型纠正。自动调整和丢弃的字段会显示在对话中，并进入后续模型上下文；没有实际页面变化的记录不计为修改，也不新增撤销步骤。`page` 操作改变主题时采用与手动选择主题相同的背景、强调色和组件继承规则，同时保留本条记录显式指定的颜色覆盖。

结构性错误（未知操作字段、不支持的组件类型、重复添加、修改不存在的组件、非法绑定/事件等）仍停止当轮请求并保留已提交组件，随后自动请求纠正，提供最新有效页面与上次错误；不会把半个组件交给 React，也不会将失败的操作当成已完成。连续两轮没有实际页面变化时暂停，避免反复消耗 token。

每条记录都有 `v:1` 和从 1 递增的 `seq`：

```json
{"v":1,"seq":1,"op":"message","text":"先布局主视觉，再补充功能与行动区。"}
{"v":1,"seq":2,"op":"page","name":"产品介绍","settings":{"maxWidth":1440,"canvasHeight":1800,"padding":24},"summary":"设置页面尺寸"}
{"v":1,"seq":3,"op":"add","id":"hero-main","type":"hero","props":{"title":"让想法成为页面"},"frame":{"x":24,"y":24,"width":1392,"height":420},"summary":"新增主视觉"}
{"v":1,"seq":4,"op":"update","id":"hero-main","props":{"text":"从灵感到上线"},"summary":"补充主视觉说明"}
{"v":1,"seq":5,"op":"done","summary":"已完成本次主视觉设计。"}
```

| 操作 | 含义 |
| --- | --- |
| `message` | 在对话中展示简短计划或说明，不改页面 |
| `page` | 合并页面名称与设置；扩展画布应先于添加底部组件 |
| `add` | 创建一个内置组件，未指定 props 使用现有组件默认值；必须给出稳定 ID 与完整 frame |
| `component` | 创建或替换指定 ID 的自定义组件；提供完整 `component` 定义或 `componentRef` 库引用，两者不可同时出现 |
| `update` | 合并指定组件的 props/frame，属性设为 `null` 表示清除（回到默认或继承样式），按需替换 bindings/events；不改 ID/type，不覆盖其他组件 |
| `remove` | 删除指定组件 |
| `data` | 按需替换变量/脚本；先建立变量，再添加引用它的绑定 |
| `ask` | 向用户提 1–4 个选择题（每题 2–6 个选项，单选题第一个为推荐，`multiple: true` 为多选）；不改页面，结束本次回复并等待回答 |
| `done` | 仅在整个用户任务完成时发送并保存摘要；仍需供应商正常结束流才视为完成 |

`component` 的完整定义包含 `name`、`html`、`css`、`js`，以及可选的 `description`、`fields`、`size`。模型不能为新源码指定库的 `source`、ID 或修订号；来源元数据由应用写入。修改源码必须使用此操作，普通 `update` 只调整实例属性、位置和联动。它不能覆盖同 ID 的内置组件。新实例未给 `frame` 时使用定义尺寸和当前页边距；页面布局建议明确给出位置，避免重叠。

```json
{"v":1,"seq":1,"op":"component","id":"interactive-card","component":{"name":"交互卡片","html":"<button data-prop=\"label\"></button>","css":"button{color:var(--as-text)}","js":"document.querySelector('button').addEventListener('click',()=>component.log('clicked'));","fields":{"label":"查看方案"},"size":{"width":360,"height":240}},"frame":{"x":32,"y":32,"width":360,"height":240},"summary":"创建交互卡片"}
{"v":1,"seq":2,"op":"component","id":"saved-card","componentRef":{"kind":"local","id":"existing-library-id"},"frame":{"x":424,"y":32,"width":360,"height":240},"summary":"复用组件库中的卡片"}
```

库引用的 `kind` 为 `local` 或 `cloud`，`id` 必须来自当前可用组件列表。页面和组件模式共用此协议；组件模式只允许开发自定义组件，不会在独立草稿中新增内置组件或页面变量／脚本。组件模式的 `update` 只用于预览位置和尺寸；字段默认值、样式和交互必须通过 `component` 写入完整定义，预览字段随定义默认值更新，保证预览、入库、上传和复用一致。页面模式仍可独立修改组件实例。

每个响应以且仅以一条结束记录收尾：`done`（任务完成）或 `ask`（等待用户选择），之后不得再有记录；只有供应商报告输出上限且剩余内容校验通过时，才允许已有结束记录完成任务；其他解析错误不会因出现 `done/ask` 而消失。完成摘要或提问也会等响应结束并校验通过后才显示。`ask` 让会话进入 `waiting` 状态，不会自动续写；用户的回答作为新消息显示，并追加到原任务后发出新请求，问题与回答都进入 `recentConversation`。系统提示要求只在新页面或需求不明确时提问，`resume`、已回答过或小范围修改时直接按合理默认值生成；同时说明画布按宽度等比缩小、不会放大：新页面使用编辑器默认的 1080p 预设（1920×1080），除非用户直接要求或在回答中选择了其他屏幕，否则保持当前画布宽高、默认在一屏内完成布局；内容确实放不下或用户需要长页面时，才在保持宽度的前提下加高画布。其他目标屏幕：2K 2560×1440、4K 3840×2160，以及笔记本 1440、平板 1024、手机 390 宽。

每个响应最多 500 条操作。序号重复且内容相同会忽略，重复但内容不同或跳号会中止当前响应并自动纠正。每个响应的协议序号从 1 开始；一次用户发送或恢复拥有一个 runId，自动续写共享该 runId，回执使用整个任务内累计序号，以 `runId:seq` 唯一标识；已有组件 ID 不能再次 add，`component` 则按稳定 ID 修改已有自定义实例。模型更新后的整份页面要通过 `validatePage` 与 500 KB 大小限制后才可提交。页面脚本仍遵循原有沙箱；自定义组件始终在 `sandbox="allow-scripts"` 的独立 iframe 中运行，不能改写编辑器代码或访问工作台存储。

## 流式传输与原子提交

OpenAI 读取 `response.output_text.delta`，Anthropic 读取 `content_block_delta/text_delta`。SSE 层处理任意网络分包、多字节字符、CRLF、心跳和多行 data；NDJSON 层只释放完整行。OpenAI 优先显示公开的 `response.reasoning_summary_text.delta`；兼容服务只有 `response.reasoning_text.delta` 时，显示接口已经返回的文本，收到摘要后替换当前轮的兼容文本，避免重复。Anthropic 显示接口公开返回的 `thinking_delta`。不读取签名、加密或脱敏内容。思考区默认只占两行，随着新内容滚动；点击展开后可阅读本次保留的完整内容，向上滚动阅读时不会被新片段拉回底部。每次任务最多在内存保留最近 12000 字符，不写入浏览器检查点或后续模型上下文；未收到可展示文本时只显示“正在思考”，不显示字数统计或空说明框。

进度面板按请求区分阶段：「正在连接模型」（尚未收到响应头）→「已连接，等待模型响应」（已收到响应头，模型排队或读取上下文）→「正在思考」→「正在生成组件」，仅显示本次任务的总耗时。某一阶段停留过久时给出对应提示（网络/代理、服务商排队），便于判断时间花在哪里。生成期间切到其他标签页时，组件之间的让帧改用计时器兜底（隐藏标签页中 `requestAnimationFrame` 不会触发），生成不会在后台停住。

SSE 不再按原始字节限制总量：每个 token 都是一条独立事件，结束事件还会重复整段输出，长回复很容易超过此前 4 MB / 单帧 1 MB 的限制，导致在最后报「响应过大」。现在只拒绝明显异常的大小（总量 256 MB、单帧 16M 字符），实际输出由最大输出 Token 约束。请求不再使用固定 10 分钟总时限，改为「5 分钟无任何数据」的空闲超时和 30 分钟单请求上限，超时会暂停并保留已完成组件，提示可继续生成。网关直接返回不带 `type` 的 `{"error": …}` 时也会立即报出其错误信息。

每一行按以下顺序处理：校验操作 → 基于最新页面计算候选 → 校验整页 → 保存浏览器检查点 → 更新画布 → 高亮与气泡 → 让浏览器绘制一帧。检查点和画布提交之间没有异步间隙。存储失败时不应用下一条操作，保留内存中的已有页面，提示导出备份。

完整源码的 `component` 操作先把生成物写入检查点，再幂等保存本机组件并补写来源检查点，最后更新页面或组件预览。本机保存失败时，完整生成物仍可从对话检查点恢复。云端上传是独立操作，不插入逐组件的同步提交过程。源码循环守卫与沙箱限制同时用于设计器、画布、分享页和原生导出；它们不能保证任意脚本都能及时终止，仍应避免长时间同步运算。

AI 读取编辑器页面时先按保存/导出的 JSON 规则建立快照，移除编辑器用于清空可选属性的 `undefined`，再进行严格校验；不会修改原页面或撤销历史。新建页面没有自定义主题时继承空数组。首次请求前会校验当前页面，避免本地数据问题引发付费重试。模型返回的 `null`、非法主题或超出数量限制仍会被拒绝，类型错误与数量超限使用不同提示。

生成期间锁住画布与会修改页面的工作台入口；浮动聊天中的暂停按钮保持可用。彩虹边缘光晕表达 AI 正在控制页面；新增/修改组件有独立高亮和描述气泡。尊重减少动态效果偏好，改为静态边框。一次用户发送或手动恢复（包括其全部自动续写请求）对应一个撤销步骤；暂停后手动编辑照常产生撤销记录。撤销掉整次 AI 生成时会提示可按 ⌘⇧Z 重做，或在 AI 对话中恢复版本。

## 版本快照

撤销历史只在内存中，撤销后再做任何编辑就会清空重做；AI 检查点又会跟随当前画布，因此单靠撤销栈无法找回被撤销的生成结果。每次运行结束（完成、提问、暂停或出错）时，只要页面有变化，就把结果保存为「AI 生成版本」；运行开始时页面非空且与已有版本不同，则保存「修改前的页面」。版本与对话按时间穿插显示，每条显示组件数与时间，可一键恢复；恢复通过普通编辑提交，本身也可以撤销；与当前画布相同的版本标为「当前画布」。每个 AI 页面最多保留 10 个版本，内容相同的页面不会重复保存。浏览器存储不足时先删除其他页面最旧的版本，再删除当前页面最旧的版本，最后才拒绝保存检查点。

## 自动续写、暂停与恢复

系统提示要求一次完成整个需求，逐组件连续输出，仅在整个任务结束时发送 `done`。正常流结束但没有 `done`、输出 token 达到上限、或组件格式/校验失败，会从最新已提交页面自动续写并携带错误供纠正；丢弃未完成 JSON，不重放已有组件。自动续写始终保持画布锁定与彩虹光晕，并在进度面板显示轮次。每次用户发送/手动恢复最多 12 个请求，连续两轮无有效页面变化则暂停。鉴权、限流、拒绝、上下文限制、网络中断、存储失败均直接暂停，不自动重试。OpenAI 的流式 refusal 事件和完成响应中的拒绝内容都会保留公开原因及已报告用量，不按缺少 `done` 自动续写。Anthropic `pause_turn` 涉及本程序未启用的服务器工具，不按普通页面续写处理。

暂停立即 abort 当前请求并解锁。未闭合的 JSON 片段丢弃，已校验完成的组件和回执保留。每轮有独立运行令牌；旧请求即使继续吐出数据，也无法修改页面或解锁后续请求。页面或账号发生变化时停止旧请求。

浏览器保存最近的页面快照、对话（含 AI 的问题）、当前任务、摘要、回执、版本、状态与 token 用量。新建时为当前页和新页面预留记录名额；记录已满时仍可管理并移除旧记录。账号记录按 userId 分区，游客记录单独存储；不会上传云端。刷新时把遗留的 running 解释为 paused，必须由用户点击继续，不自动消耗 API 额度；等待回答的 waiting 状态保留，问题仍可作答。聊天收起时 AI 提问会自动展开聊天，启动按钮上也会显示待回答标记。恢复使用当前页面作为事实来源，结合任务与已完成摘要重新生成；每次页面激活（包括延迟到达的云端页面）或跨标签页记录刷新都会重新比较检查点；不同则必须显式恢复检查点或选择当前画布，不能先覆盖较新的检查点。恢复选择未完成时，人工修改（包括仅改页名）不会覆盖检查点。用户选择「使用当前画布」后，人工修改才成为后续检查点。生成锁只禁止用户操作，程序仍会平移视野并在必要时缩小视野，让正在更新的组件可见；不会改动保存的组件坐标。其他标签页更新 AI 记录时，当前生成暂停以避免相互覆盖。

写入对话记录前按持久化 JSON 形状校验；输入空页名等临时状态不会覆盖最后有效检查点，修正后继续保存。读取时逐条隔离无效记录，其余会话仍可使用；下次覆盖前将无效原始记录保存到该账号独立的 `:unreadable` 备份键，备份失败则保留原记录并报错。

## 定向修改与生成检查

请求包含发送时选中的有效组件 ID。用户描述「这个按钮」「所选组件」时，模型据此定位；任务开始时的选择保存在会话中，自动续写、手动继续及刷新恢复均沿用它，不会随生成高亮转向新组件；新任务使用当前选择，已删除的组件会过滤掉。选择只是上下文，不会扩大用户要求的修改范围。

组件 ID 同时是页内导航目标，`#pricing` 可跳到 ID 为 `pricing` 的组件。预览、分享和导出使用同一规则；保留模板的 `#features`、`#about`、`#contact` 别名，同名组件 ID 优先。

任务完成后，对话显示辅助质量检查并可定位相关组件：检查画布越界、可能的重叠和缺失锚点；有可测量的渲染内容时，还检查组件内容溢出和已知纯色背景上的文字对比度。检查不会自动改动页面或发起付费请求；图片、渐变、动态交互等仍需要预览确认。

## Token 成本

- 系统提示固定（利于供应商前缀缓存），包含每个组件的自然尺寸、显示内容与条目格式（由组件目录自动生成，去掉只对编辑器有意义的说明）、样式属性的实际绘制范围（`background` 铺满外框、`accent` 是填充与高亮、`color` 是文字色）、栅格与间距、`contentScale` 的用法，以及精简通用属性协议；不重复塞入全部官方 Motion Schema。
- add 只输出相对默认值的差异，update 只输出本次改变的字段；不回传整个页面。
- 每轮使用最新目标快照替代历史页面版本；目标中的自定义源码保留，以便继续编辑。组件库只发送摘要，最多 300 条、约 60000 字符，超出的条目数量会告知模型。
- 携带最近 10 条对话、最近 30 条操作摘要及一份任务摘要；存储保留最近 60 条对话、100 条回执，最多 12 个 AI 页面。
- 上下文大小有硬上限；UI 的预估 token 仅用于比较成本，实际计费以供应商 usage 为准。中断的请求可能未返回 usage，已报告用量不能作为完整账单。单轮输出上限由用户配置；达到上限自动从检查点续写，各轮 usage 累加。总请求轮数与连续无进展限制避免无限续写；每轮仍会产生正常的输入与输出费用。
- 不假设 `previous_response_id` 会消除历史 token 费用，也不依赖服务端保存对话，从而可以切换供应商并在中断后重建上下文。
