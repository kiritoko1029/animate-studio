# Animate Studio 低代码平台完善计划书

> 文档性质：产品与技术路线建议，不代表功能已经实现。里程碑以验收结果为准，不在团队规模尚未确定时承诺固定日期。

## 一、目标与定位

Animate Studio 已具备自由画布、88 种组件、变量与事件、脚本沙箱、自定义组件、云端页面、分享、代码导出，以及可持续修改页面的 AI 对话能力。下一阶段应从“AI 辅助的单页编辑器”发展为“普通用户也能完成数据驱动网站和轻量业务应用的低代码平台”。

平台目标不是堆出最多按钮，而是让用户始终能用同一种方式完成任务：

**说明目标 → 选择推荐结果 → 画布中微调 → 预览确认 → 发布或导出。**

### 核心原则

1. **默认简单，能力不删减**：常用配置直接显示，专业配置收进“高级”，不是移除高级功能。
2. **先完成任务，再解释概念**：用户先看到可用结果，再按需理解数据源、绑定、路由等术语。
3. **所有复杂对象都可视化**：数据、列表、图表、页面和发布状态都有明确的管理入口与状态反馈。
4. **AI 是操作入口，不是黑箱替代品**：AI 能创建、连接、解释和修复，但用户始终可预览、撤销和手动继续。
5. **一个渲染与数据契约**：编辑、预览、分享和导出行为一致，避免“编辑器可用，导出后失效”。
6. **兼容已有作品**：新增能力通过版本化迁移加入，不要求用户重建页面，不改变旧页面默认外观。

## 二、降低学习成本的统一设计

### 2.1 用任务组织功能，而不是用技术概念组织功能

首页提供“制作网站”“制作数据看板”“制作内部工具”“创建可复用组件”等入口。选择后加载带示例数据的完整模板，用户先替换内容，再逐步连接真实数据。

统一为四个用户步骤：

| 步骤 | 用户看到的内容 | 默认隐藏但保留的能力 |
| --- | --- | --- |
| 创建 | 模板、AI 描述、空白页面 | 页面 JSON、画布参数 |
| 编辑 | 内容、样式、布局 | 高级动效、图层细节、代码 |
| 连接 | 数据、页面跳转、表单动作 | 表达式、脚本、请求细节 |
| 交付 | 预览、检查、发布、导出 | 环境、部署和调试配置 |

### 2.2 渐进式披露，而非简化版与专业版分裂

- 属性面板统一为“内容 / 样式 / 交互”，高级项放在各页底部或统一“高级”区域。
- 所有组件开箱即用，带合理示例内容、尺寸、空状态和加载状态。
- 常用操作支持画布内直接编辑；双击改文字，选中后改数据，右键进入高级设置。
- 控件使用用户语言，例如“显示这些数据”优先于“配置集合绑定表达式”。
- 高级功能支持搜索和“跳转到此设置”，避免藏得深等于找不到。
- 用户的展开状态按账号保存；新手看到简洁界面，熟练用户不会每次重复展开。
- 所有 AI 修改和自动修复都可撤销；危险操作必须确认，不用“防止误操作”为理由删除能力。

### 2.3 建立一致的心智模型

所有数据驱动组件遵循同一流程：

**选择数据 → 选择显示方式 → 映射字段 → 设置交互。**

无论表格、列表、图表或详情页，都复用数据选择器、字段映射器、筛选器和状态配置。脚本继续作为高级扩展入口，但不要求普通用户先理解 `ctx` 或 JavaScript。

## 三、功能建设计划

### 3.1 多页面与站点能力

现有“云端多页面保存”继续保留，新增的是页面之间的站点关系，而不是另一套页面库。

- 站点页面树、分组、复制、排序和页面级草稿。
- 首页、普通页面、404 和动态详情页。
- `/products/:id` 等动态路由，页面可读取路由参数。
- 页面间跳转动作、返回、导航选中状态和访问权限。
- 全局页头、页脚与共享布局；修改共享布局可选择应用到哪些页面。
- 发布时以站点为单位，导出时保留页面与导航关系。

**简化设计**：默认只显示“页面”列表；“路由规则”“动态参数”在创建详情页时由模板自动填写。

### 3.2 无代码数据中心

现有脚本 `ctx.fetchJSON` 保留为高级方式，新增可视化数据源。

- REST API 为首批连接类型，后续增加 GraphQL、数据库和托管内容集合。
- 地址、方法、参数、请求头、鉴权、超时和测试请求。
- 从示例响应自动推断字段类型，允许手动修正。
- 查询支持筛选、排序、分页、刷新、缓存和依赖参数。
- 统一的加载、空数据、错误和离线状态。
- 密钥仅保存在服务端凭据存储或受控环境中，不进入页面 JSON、模型上下文、分享快照或导出文件。
- 外部写操作与读操作分开授权，提供请求预览和影响说明。

**简化设计**：用户粘贴接口地址并点击“测试并连接”，系统生成推荐字段；只有鉴权、分页和异常时才展开高级设置。

### 3.3 动态列表、详情与表单

- Collection/Repeater 将数组渲染为卡片、列表或自定义布局。
- 子组件可绑定 `item`、`index` 和当前作用域字段，无需手写表达式。
- 静态数组、页面变量、API 查询和 CMS 集合使用同一数据接口。
- 列表项支持点击打开详情、编辑、删除和确认动作。
- 表单增加必填、格式、长度、跨字段校验和清晰的字段错误。
- 提交支持 API、新建/更新内容集合、成功跳转和失败重试。
- 文件与图片上传、批量编辑、多步表单作为后续扩展。

**简化设计**：选中列表后只问“显示什么数据”和“每项使用什么模板”；平台自动生成首项模板和字段映射。

### 3.4 图表与数据看板

- 首批：折线图、面积图、柱状图、条形图、饼图/环形图。
- 第二批：组合图、散点图、漏斗图、雷达图和仪表盘。
- 通用配置：多系列、坐标轴、图例、提示框、标签、颜色、网格、空状态和刷新。
- 图表与其他组件使用相同的数据源、筛选和字段映射，不建立独立的数据体系。
- 支持图表联动筛选、点击下钻、导出 PNG/SVG，以及数据表格替代视图。
- 图表库选型必须通过体积、交互、主题、导出、可访问性和运行时兼容验证，不直接凭生态热度决定。

**简化设计**：AI 或模板先给推荐图表，用户通过“图表类型”一键切换；字段不正确时给出可读提示，不显示空白图表。

### 3.5 内容、媒体与响应式

- 媒体库：上传、文件夹、搜索、替换、裁剪、焦点和授权状态。
- CMS 内容集合：文章、产品、案例等结构化内容，与页面分离维护。
- 富文本/Markdown：正文、列表、链接、引用和代码内容。
- SEO：标题、描述、分享图、canonical、robots 和 sitemap。
- 多语言：语言版本、翻译状态、语言切换和本地化链接。
- 响应式：默认提供“自动适配”，高级模式允许按断点调整位置、尺寸、显隐和样式。

**简化设计**：普通用户只选择“桌面和手机都适配”；具体断点只在用户主动调整时出现。固定画布继续作为需要精确设计的高级模式，不强制迁移旧页面。

### 3.6 发布、协作与治理

- 草稿、预览、发布、更新、回滚和定时发布。
- 页面级评论、修改历史、版本对比和恢复。
- 角色权限、审核流程、页面密码和团队成员管理。
- 自定义域名、多环境和发布状态记录。
- 可访问性检查、性能预算、错误监控和基础访问统计。

发布始终明确区分“保存草稿”“更新分享”“正式站点发布”，避免一个按钮产生超出用户预期的外部影响。

## 四、AI 能力扩展计划

现有 AI 已能逐组件生成页面和自定义组件、定向修改、提问、恢复版本及做基础质量检查。下一阶段应让 AI 覆盖完整任务链，而不只生成视觉布局。

### 4.1 从“页面生成器”升级为“低代码协作者”

| 用户表达 | AI 应完成的工作 | 用户只需确认 |
| --- | --- | --- |
| “做一个产品官网” | 规划页面、共享布局、导航、内容和 SEO | 风格与主要页面 |
| “连接这个接口并展示产品” | 测试读取、识别字段、创建列表与详情 | 地址、鉴权和字段映射 |
| “把这些数据做成看板” | 推荐图表、映射指标与维度、配置筛选 | 图表类型和重点指标 |
| “让表单可以提交” | 配置校验、提交动作、成功与失败状态 | 写入目标及权限 |
| “手机上也整理好” | 生成断点适配并检查溢出、遮挡和字号 | 预览关键页面 |
| “检查并修复这个页面” | 检查链接、溢出、对比度、状态和交互，提出修复 | 是否应用每项修复 |
| “解释这个联动” | 用页面实际数据解释触发条件与修改路径 | 是否继续修改 |

### 4.2 AI 的四种固定角色

1. **创建者**：生成页面、站点、数据绑定、图表、表单和自定义组件。
2. **讲解员**：解释当前设置、指出操作位置、用用户页面举例，而不是只给通用教程。
3. **检查员**：结合真实渲染、控制台和交互状态发现问题，不只看 JSON。
4. **修复者**：给出可审阅的修改计划，按范围执行，保留前后版本和撤销入口。

### 4.3 AI 必须遵守的产品边界

- AI 使用与手动编辑相同的组件、数据和校验能力，不绕过平台约束。
- 操作协议按能力版本扩展，并保留稳定 ID、修订前提、原子提交和检查点。
- 每次任务先说明范围；跨页面、删除数据、外部写入、发布和域名修改必须显式确认。
- 密钥、令牌、私密环境变量不得发送给模型，也不得写入导出内容。
- AI 结果先进入草稿，不自动覆盖正式版本。
- 大改动提供前后差异；小改动可直接应用，但都保留撤销。
- 失败时保留可用结果，并给出“重试 / 手动处理 / 恢复版本”，不无限消耗额度。
- 用户可选择是否保存偏好；可查看和清除，不建立不可见的用户画像。

### 4.4 用 AI 降低学习成本，而非增加新术语

- 对话中提供“连接数据”“制作图表”“检查手机效果”等可点动作。
- AI 提问只收集会改变结果的信息，并优先给推荐选项。
- 完成操作后指出“在哪里继续修改”，把结果和教学结合起来。
- 用户选中组件后可直接说“这个”“这里”“让它可点击”，复用现有选择上下文。
- 对高级设置提供“帮我配置”，执行后仍展示实际产生的配置，避免形成无法维护的黑箱。

## 五、技术演进要求

### 5.1 文档与 Schema

在现有 `PageDocument` 之上逐步引入版本化的站点、数据源、查询、内容集合、路由、资产和发布定义。每次扩展都必须同时覆盖：

- 浏览器模型与共享校验。
- Node、Cloudflare 和数据库迁移。
- AI 操作协议与权限检查。
- 编辑、预览、分享、导出和旧版本迁移。
- 对应声明文件、测试和用户文档。

旧页面继续以单页站点打开；迁移失败时保留原始 JSON 和恢复入口。

### 5.2 能力注册表

逐步让组件目录同时描述：默认配置、可绑定字段、数据能力、交互能力、AI 指南和质量检查。组件面板、属性编辑器、AI 上下文和文档从同一来源生成，减少“界面支持但 AI 不知道”的偏差。

### 5.3 数据与安全

- 读取、写入、发布分别授权，并记录可审计的操作摘要。
- 服务端代理只承载需要保密或跨域控制的连接，普通公开接口仍可直接访问。
- 查询和 AI 操作都有超时、取消、大小限制与速率限制。
- 自定义组件继续运行在现有沙箱中，不因为数据能力获得父页面或账号权限。

### 5.4 质量与性能

- 每个里程碑同时验证编辑、预览、分享和 HTML 导出；Vue/React 包装按既有契约复测。
- 为常用任务建立真实浏览器端到端场景，不用单元测试代替布局与交互验证。
- 对图表、大列表和多页面设置明确的初始加载与更新性能预算。
- 功能通过增量发布和开关逐步开放，旧作品不因新功能失败而无法编辑。

## 六、里程碑与验收

### M0：统一体验与技术底座

**交付**：任务式导航和属性面板原型、用户任务基线、站点/数据 Schema 设计、能力注册表方案、旧文档迁移策略。

**验收**：新手不阅读文档，能通过模板完成首个页面；现有作品、AI 会话和导出行为不回归。

**阶段拆分与进度**：

- **M0-1 已交付**：页面菜单中的任务式创建对话框，支持网站、数据看板、内部工具和 AI 创建入口；三类模板均可编辑，保留草稿撤销与既有导出。看板和内部工具明确使用示例数据，不代表 API、真实图表或 CRUD 已完成。已通过全量自动化测试、生产构建和桌面/移动 Chrome 创建、编辑、撤销、AI 无请求、预览及 HTML 下载验收。
- **M0-2 已交付**：常用内容、布局、外观和入场动效直接可见，整体缩放、官方属性和附加动效进入高级折叠；单组件、多选和自定义组件均可按名称或官方路径搜索并展开聚焦。右键“高级设置…”复用同一展开逻辑，支持键盘、输入法和读屏当前结果；搜索与展开不产生页面撤销记录。已通过全量自动化测试、生产构建及真实 Chrome 单组件/批量/自定义、官方字段编辑和窄屏验收。
- **M0-3 已交付**：单组件、批量、自定义组件与官方属性组按稳定的组件类型和设置组键保存展开状态；游客保存在当前浏览器，账号云端隔离恢复，并支持记住默认展开组的收起状态。搜索和右键只临时展开，不写入偏好；恢复不产生云端写入，偏好不进入页面 JSON、撤销历史或导出。主题与展开状态按字段独立合并，已提供 D1、SQLite、PostgreSQL 迁移。全量测试 410/410 通过，Node 与 Cloudflare 构建通过；真实 Chrome 已验证键盘操作、同类型实例、游客刷新恢复及窄屏，账号流程由 SQLite API 与编辑器集成测试覆盖。PostgreSQL 后端未配置一次性测试库，未实测。
- M0 的用户研究、站点/数据 Schema 和能力注册表设计随对应后续阶段完成，不以 M0-1、M0-2 的界面交付代替。

### M1：多页面与 AI 站点创作

**交付**：页面树、共享布局、基础路由、页面跳转、站点预览；AI 可创建整站并解释结构。

**验收**：用户可完成“首页 → 列表 → 详情”的站点；共享布局修改可按确认范围同步；导出与分享导航一致。

**阶段拆分与进度**：

- **M1-1 已交付**：版本化 `SiteDocument` 与严格校验，旧页面自动作为单页站点打开；左侧页面树支持分组、创建、复制、重命名、设为首页、排序和删除确认。游客使用独立站点草稿键，云端复用原页面记录升级为站点，不建立第二套页面库；站点保存具备修订前提和 409 冲突保护，分享沿用原令牌。
- **M1-2 已交付**：普通页面、详情页与 404，支持 `/products/:id` 路径参数和 `route.id` 只读表达式、返回动作、站内页面选择器及导航选中状态。编辑预览使用独立历史，分享使用 `/p/<令牌>/<路径>`，单文件 HTML 使用可刷新恢复的 `#/路径`；Vue/React 继续复用同一导出运行时。
- **M1-3 已交付**：共享页头、页脚可直接使用原画布与组件编辑；应用范围按页面勾选并确认，一次批量应用可撤销。组合渲染保留正文与布局的独立内容，支持分享和导出；重复变量和合并后超过画布上限会明确拒绝。
- **M1-4 已交付**：AI 整站任务先给出页面、路由、布局和删除范围计划，用户确认后才生成；每页和布局均通过平台校验，生成先进入独立检查点，完成后一次应用，可撤销或恢复生成前版本。支持暂停、继续、结构解释、损坏检查点保护和最终修订检查；单页与整站任务不能同时修改同一作品，AI 不自动发布。
- **边界**：动态路由只负责页面与参数，不代表已接入真实 API、CMS、Repeater 或表单提交。访问权限、SEO、可视化数据源与图表仍分别属于 M2–M4，不在 M1 标记完成。

## 七、衡量是否“简单又完整”

以下为首轮建议目标，实施前先用当前版本记录基线，再按实际用户调整：

| 维度 | 指标 |
| --- | --- |
| 上手 | 新用户不读文档，5 分钟内得到可预览的有效页面 |
| 任务完成 | 模板建站、数据列表、图表、表单等核心任务有独立成功率，不用点击量代替成功 |
| 可理解性 | 用户能说出数据来自哪里、修改会影响哪里、当前是否已发布 |
| AI 质量 | 统计首次可用率、人工接管率、修复率和撤销率，而不只统计生成次数 |
| 功能完整 | 高级功能仍可发现、可使用；渐进展示不能导致功能入口不可达 |
| 安全 | 外部写入、删除和发布 100% 有明确授权；秘密信息不进入页面和模型上下文 |
| 一致性 | 编辑、预览、分享和导出通过同一批关键场景 |
| 性能 | 大列表和图表更新时画布保持响应；AI 生成期间暂停、对话和手动接管始终可用 |

每个里程碑至少邀请一组首次使用者和一组熟练用户验证。前者发现学习成本，后者确认功能没有被“简单化”削弱。

## 八、主要风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 功能增多导致界面拥挤 | 任务导航、上下文属性、高级区、全局搜索，不持续增加顶层按钮 |
| AI 做了用户无法理解的操作 | 操作摘要、差异、定位、撤销和“解释此配置” |
| 数据与自定义组件扩大攻击面 | 沙箱、权限分离、秘密隔离、请求限制和发布确认 |
| 新 Schema 破坏旧页面 | 版本化迁移、原始备份、双运行环境测试和可恢复升级 |
| 图表与大列表拖慢画布 | 数据采样、按需加载、虚拟化和独立性能预算 |
| 自动适配改变设计稿 | 保留固定画布模式，响应式修改提供预览和逐项确认 |
